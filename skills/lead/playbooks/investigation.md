### Investigation

**You own the answer. Plan, route, write.**

An investigation is read-only. It produces a cited explanation or a recommendation, not a code change.

1. Route the question through the **how** skill (`../how/SKILL.md`). For a question about motivation or history, also route it through the **why** skill (`../why/SKILL.md`).
2. Produce the `how`-shaped output (Overview, Key Concepts, How It Works, Where Things Live, Gotchas). When the request is a decision between alternatives, produce a recommendation with a tradeoffs table.
3. Apply the **unslop** skill (`../unslop/SKILL.md`) to the reply.

No PR, no babysit, and no `architect` unless the investigation precedes a code change. If it does, hand the answer back to the person and re-route to Bug fix or Feature.

**Reply:** the investigation output. For an "are we sure?" question, include your real judgment with reasons. Push back if the premise is wrong.
