### Refactoring

**You own the contract. The structure changes. The behaviour does not.** Distinct from Feature, which adds behaviour, and Bug fix, which corrects it.

If the cleanup reveals a missing feature or a real bug, split it out and ship the structural change first against the pinned contract. A redesign is allowed, but name it and route to Feature. Large or cross-cutting structural work belongs to the **figure-it-out** skill (`../figure-it-out/SKILL.md`). This playbook is the focused-to-medium change.

1. **Pin the behaviour contract first.** Learn the contract with a lookup over the affected subsystem through the **how** skill (`../how/SKILL.md`). Then have a characterization test, snapshot, or equivalence harness written that captures current behaviour before any structure moves. If the area has no coverage, the pin comes before any structural edit. Type check and lint are not a pin.
2. **Name the structure the code is missing**, per the **principle-model-the-domain** skill. Boring code stays when the shape is already clear and local. The reshape must delete branches or invalid states, not add indirection.
3. **Name the target shape.** State what the module layout, types, and call graph should be if built today (the **principle-foundational-thinking** and **principle-redesign-from-first-principles** skills). If the target crosses a function boundary, run the **architect** skill (`../architect/SKILL.md`) before the move.
4. **Subtract before you add.** Delete dead code, collapse one-caller wrappers, drop redundant validators, and remove orphan references before introducing the new shape (the **principle-subtract-before-you-add** skill). The smallest change that reaches the target shape ships (the **principle-laziness-protocol** skill). A speculative cleanup that "might help" gets reverted.
5. **Move in small behaviour-preserving steps, each keeping the pin green.** Write the steps as slices with the **outline** skill (`../outline/SKILL.md`): the pin, then the subtraction, then the reshape, then any follow-on cleanup. Each slice's verify command runs the pin. Run the **build** skill (`../build/SKILL.md`). A one or two file reshape goes inline, as in the Quick playbook. For an API reshape, one slice migrates every caller and deletes the old API (the **principle-migrate-callers-then-delete-legacy-apis** skill). No compatibility shims, no parallel old-and-new paths. Name the symbols being moved in the brief, and have the checker spot-check every rename against the actual files. Renames silently miss usages in strings, prose, and back-references.
6. **Prove behaviour is unchanged on the real artifact**, not "it compiles" (the **principle-prove-it-works** skill). For a larger reshape, run an equivalence check: a script that diffs old against new outputs, a recorded baseline replayed against the new code, or a smoke run on the matching surface.
7. **Confirm the change is worth keeping.** The success measure is reduced reader load (the **principle-minimize-reader-load** skill). If the diff does not lower reader load somewhere, revert it.
8. Run the **review** skill (`../review/SKILL.md`), then the **open-pr** skill (`../open-pr/SKILL.md`) with the person's consent. The commits stay in slice order: the subtraction, then the reshape, then the cleanup.

**Reply:** the structure that changed, the pin you held it against, the equivalence proof, the reader-load delta, what shipped and what got reverted. No new behaviour.
